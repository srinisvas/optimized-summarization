Executive Summary
Cloud Computing has profoundly revolutionized data handling by offering instantaneous access to virtually unlimited resources, yet its broader adoption is significantly hampered by widespread fears regarding privacy and security issues, coupled with a fundamental lack of control over proprietary data. The core argument of this paper is that existing privacy protection solutions are insufficient because they typically focus on a single aspect while being unduly complex, often promoting system misconfiguration. When fine-grained configuration possibilities become too complicated, users struggle to cope with too many choices, frequently resulting in less protected systems. To address this critical gap, the paper introduces "Software Defined Privacy" (SDP), a novel concept inspired by other software defined systems that emphasizes the orchestration and combination of various, already existing privacy protecting approaches into one centralized place.

The Software Defined Privacy framework is designed to allow IaaS Cloud Customers to easily describe and enforce their specific privacy requirements through adequate policies, without requiring awareness of the underlying technical details or the tools in use. Following the typical structure of Software Defined Architectures—split into Application, Control, and Infrastructure layers—the system simplifies complexity by offering users default configuration categories. For instance, upon instance creation, selecting a high default category, such as "secret," automatically deploys appropriately configured tools; this could involve disabling backups or setting the requirement for exclusive usage of physical resources to protect against Intra Host Attacks. This approach not only provides easier scalability by enabling scale-out instead of scale-up but also allows the user to further define detailed needs, including using an XML-based interface for specialized "Privacy Officers" to design tailored rule sets for a particular Virtual Machine.

Through this decoupled configuration and enforcement mechanism, SDP enables the cloud customer to protect against various threats, including transborder data flow—an issue gaining prominence following events like the fall of the "Safe Harbor" agreement. While traditionally detecting data leaks was mostly done at network perimeter devices, an inefficient and static approach for cloud environments, the SDP system utilizes a Privacy Breach Prediction Agent. This agent parses the configuration files and compares them to the original privacy policy to detect improper configurations. The user remains in control, capable of either loosening suggested mitigation methods or implementing even more robust protection mechanisms. This work concludes that SDP offers a powerful, policy-driven paradigm for enforcing comprehensive cloud privacy requirements.
